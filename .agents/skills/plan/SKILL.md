# Plan

Read `CONSTITUTION.md` and the spec for the part you are changing. Do
not write product code. Do not build `docs/roadmap.md` unless the spec
has moved.

Propose a plan. File issues only when the user agrees, using
`.agents/skills/create-issue/SKILL.md`. Reuse an existing open issue
when it already is this work.

Create issues for the work. Try to break a large problem into more
than one issue when that helps. One issue is fine when the change is
already small. Parallel work is best effort: one checkout is one
branch, and overlapping files are easier sequential than concurrent.

Each issue needs a title, goal, acceptance, and specs. Add details,
files, and blocked-by when they help. The goal can include known
implementation notes. Do not squeeze it.
